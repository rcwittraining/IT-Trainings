The clock-skew line matters.

Kerberos tolerance is five minutes by default. A domain controller four minutes out of skew can produce failures that look like an attack, and can mask ones that are real. Note it before you conclude anything about authentication.

Objective 1

Triage decision

Required
Reading the alerts

What each one really claims

Kerberoasting (4401)
Service tickets requested for SPNs with weak history. It proves *requests*, not a cracked password — say so in the record.
Account mapping (4402)
A machine account enumerated the privileged groups. Normal for some scanners, so look at the source: it came from a workstation session, not a service.
DCSync (4403)
GetChangesAll requires replication rights. If the account legitimately has them, this is a permission design problem as much as an attack.
Honeytoken (4404)
Definitive. Anything that touches it is in the environment with credentials it should not possess.
Backup enumeration (4405)
Matches a change record. Suppress narrowly, with an owner and an expiry — do not turn off the detection class.

Traps in this lab

Six things that cost points on purpose

  1. “Both DCSync accounts are attacks.” One is the sync account by design. Verify the source host before you disable a connector and stop the directory synchronising.
  2. Password reset before token revocation. The refresh token keeps minting access tokens after the reset; the attacker does not notice for hours.
  3. Cloud-only disable of a hybrid account. On-premises Kerberos keeps working; the record must state both actions.
  4. Excluding an alert category to please a queue. Approve the narrow request, refuse the category, and treat a 05:01 request to mute the honeytoken as an indicator.
  5. Disabling LDAP signing as “hardening”. It is the opposite; the option is there to be resisted.
  6. Importing last week's regulator. DORA's four-hour clock belongs to financial entities. This tenant is an essential entity under NIS2 with GDPR duties — read the entity, not the habit.

Limits

What this replica cannot teach you

  • No directory is queried, so you will not learn the PowerShell module, repadmin output or the shape of a real replication metadata dump.
  • No Entra tenant, so the portals' latency, licensing gates and conditional-access evaluation What-If are absent.
  • Six tables with a handful of rows: real hunting is dominated by schema discovery, retention surprises and query cost, not syntax.
  • Nothing here rehearses the human part: the 06:15 phone call, the trust you lose by over-claiming, the negotiating with the payroll team about a two-week fix.

Everything is deterministic and offline; the state lives in your browser's localStorage and is wiped by the reset control.
